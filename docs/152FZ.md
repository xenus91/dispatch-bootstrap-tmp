# 152-ФЗ: обработка персональных данных

Система обрабатывает персональные данные. Документ описывает, что именно
обрабатывается, что уже сделано в коде, что обязан сделать оператор, и даёт
шаблоны документов.

> **Важно.** Часть обязанностей лежит на **операторе** персональных данных —
> это заказчик, а не разработчик. Уведомление в Роскомнадзор подаёт оператор
> (ст. 22), назначает ответственного, утверждает политику. Наша зона —
> техническая реализация и шаблоны документов, готовые к подаче.

---

## Какие данные обрабатываются

| Таблица | Категория | Что хранится |
|---|---|---|
| `staff` | ПДн работника | ФИО, номер телефона, идентификаторы и username в MAX, гос. номер тягача, примечания |
| `sessions` | ПДн работника | IP-адрес, user-agent, устройство, время сессии |
| `access_events` | ПДн работника | Телефон, идентификатор MAX, события входа |
| `otp_codes` | ПДн работника | Код входа (одноразовый) |
| `invites` | ПДн работника | Код приглашения, срок действия |
| `status_history` | ПДн работника + геолокация | **Широта и долгота** водителя, имя актора, комментарий |
| `attachments` | ПДн и коммерческая тайна | **Фотографии** товарно-транспортных документов и актов |
| `points` | ПДн контакта | Название и адрес пункта, контактное лицо, телефон, координаты |
| `clients` | ПДн контрагента | Наименование, **ИНН**, адрес, контактное лицо, телефон, e-mail |
| `requests` | Коммерческая тайна | Номер контейнера, вес груза, маршрут, комментарий |
| `bot_state`, `bot_outbox` | ПДн работника | Состояние диалога, тексты сообщений |

**Биометрические данные не обрабатываются.** Голосовые сообщения не
распознаются, фото не анализируется — вложения хранятся как файлы.

**Данные о местоположении** (широта/долгота) обрабатываются и относятся к
специальной категории — их обработка требует письменного согласия по ст. 10.

## Что уже сделано в коде

| Требование | Реализация |
|---|---|
| Локализация БД (ч. 5 ст. 18) | PostgreSQL на VPS в РФ. База на территории РФ — обязательное условие с 01.07.2025 |
| Трансграничная передача (ст. 12) | Убраны сторонняя аналитика и Google Fonts. Внешних обращений к сервисам вне РФ нет |
| Разграничение доступа (ст. 18.1) | Роли admin / dispatcher / driver на уровне процедур API |
| Регистрация событий доступа | Таблица `access_events`, выводится в панели «Сотрудники» |
| Срок жизни сессий | 12 ч (браузер), 30 дн (Mini App), настраивается в панели |
| Ограничение хранения | `processed_updates` — 3 дня (автоочистка в планировщике), сессии — по TTL |
| Право на отзыв согласия | Есть блокировка доступа; полноценное удаление данных — в работе |
| Транспортная защита | HTTPS (TLS 1.2+), `scram-sha-256` в PostgreSQL, сессии — случайные 32-байтовые токены |
| Отсутствие cookie | Панель работает на Bearer-токене в `localStorage` — cookie-баннер и согласие на cookie не требуются |
| **Явное согласие (ст. 9, 10)** | Отдельный шаг в боте MAX перед активацией: «Согласен / Не согласен». В панели — чекбокс на странице входа. Версия согласия хранится рядом с субъектом |
| **Политика в открытом доступе (ст. 18.1)** | Страница `/privacy` открыта без авторизации, ссылка на странице входа |
| **Выгрузка данных (ст. 14)** | Кнопка в карточке сотрудника: JSON со всеми данными — карточка, сессии, коды, приглашения, журнал доступа, история, заявки |
| **Удаление данных (ст. 15, 17)** | Кнопка в карточке: субъект обезличивается, следы в операционных таблицах вычищаются, согласие снимается |
| **Журнал действий (ст. 19)** | Таблица `audit_log`: кто, что, когда, с какого IP. Страница «Журнал действий» в панели |
| **Журнал доставки событий** | Таблица `webhook_events`: сколько событий пришло, обработано, отброшено как дубль, отклонено по секрету |

## Паспорт ИСПДн (шаблон)

```
Наименование: ИСПДн «Диспетчерская контейнерных перевозок»
Оператор:     <наименование юридического лица>, ИНН <...>, ОГРН <...>
Ответственный за организацию обработки: <ФИО>, должность, контакт

Цели обработки:
  - управление заявками на перевозку контейнеров;
  - контроль исполнения маршрута водителем;
  - уведомление участников процесса;
  - обеспечение безопасности доступа к системе.

Категории субъектов: работники (водители, диспетчеры, администраторы),
  представители клиентов-контрагентов.

Категории данных: ФИО, номер телефона, идентификатор аккаунта в мессенджере,
  гос. номер транспортного средства, данные о местоположении, изображения
  товарно-транспортных документов, реквизиты контрагентов (наименование, ИНН,
  адрес, контакты), сведения о заказах и грузах.

Перечень действий: сбор, запись, систематизация, накопление, хранение,
  уточнение, извлечение, передача (внутри организации), обезличивание.

Сроки хранения:
  - карточки сотрудников   — до увольнения + 3 года;
  - сессии                  — до 30 дней с момента последнего использования;
  - журнал доступа          — 12 месяцев;
  - коды входа и приглашений — до истечения срока действия;
  - заявки и история по ним — 5 лет с даты закрытия заявки;
  - вложения (фотографии)  — 5 лет с даты закрытия заявки.

Место хранения: база данных PostgreSQL на сервере, расположенном на
  территории Российской Федерации. Резервные копии — там же, срок хранения
  7 дней.

Меры защиты:
  - разграничение доступа по ролям (администратор / диспетчер / водитель);
  - шифрование канала передачи (TLS);
  - хеширование паролей не применяется — используются одноразовые коды;
  - журналирование действий по доступу;
  - автоматическое завершение сессий;
  - блокировка входа при неудачных попытках;
  - регулярное резервное копирование и проверка восстановления;
  - антивирусная защита сервера и регулярное обновление ПО.

Трансграничная передача: не осуществляется.
```

## Шаблон политики обработки ПДн

Размещается по адресу `/privacy` в панели и в открытом доступе.

```
ПОЛИТИКА ОБРАБОТКИ ПЕРСОНАЛЬНЫХ ДАННЫХ

1. Общие положения
1.1. Настоящая Политика определяет порядок обработки персональных данных
     и меры по обеспечению их безопасности в информационной системе
     «Диспетчерская контейнерных перевозок» (далее — Система).
1.2. Оператор персональных данных: <наименование>, ИНН <...>.
1.3. Ответственный за организацию обработки: <ФИО>, <контакты>.

2. Перечень обрабатываемых данных
   <перечислить категории — см. раздел «Какие данные обрабатываются»>

3. Цели обработки
   <перечислить цели>

4. Правовые основания
   Исполнение трудового договора; заключение и исполнение договоров с
   клиентами и перевозчиками; согласие субъекта персональных данных
   (ст. 9 152-ФЗ); законодательство Российской Федерации.

5. Порядок и условия обработки
   Обработка с использованием средств автоматизации. Данные обрабатываются
   на территории Российской Федерации.

6. Сроки хранения
   <перечислить — см. паспорт ИСПДн>

7. Передача третьим лицам
   Оператор не передаёт персональные данные третьим лицам, за исключением
   случаев, прямо предусмотренных законодательством.
   Трансграничная передача не осуществляется.

8. Права субъекта персональных данных
   Субъект вправе:
   - получить сведения об обработке своих персональных данных;
   - требовать уточнения, блокирования или уничтожения данных;
   - отозвать согласие на обработку;
   - обжаловать действия оператора в Роскомнадзор или в суд.
   Для реализации прав обратитесь к администратору Системы.

9. Меры защиты
   <перечислить — см. раздел «Меры защиты» паспорта ИСПДн>

10. Ответственность
    Оператор несёт ответственность за нарушение требований законодательства
    о персональных данных.
```

## Шаблон согласия на обработку

Выводится при активации сотрудника в боте MAX и на странице входа в панель.

```
СОГЛАСИЕ на обработку персональных данных

Я, <ФИО>, подтверждаю, что даю согласие <наименование оператора>
(ИНН <...>), адрес: <...>, на обработку следующих персональных данных:

  - фамилия, имя;
  - номер телефона;
  - идентификатор аккаунта в мессенджере MAX;
  - государственный регистрационный номер транспортного средства;
  - данные о моём местоположении (широта, долгота) — при отметке
    прибытия на пункт маршрута;
  - изображения товарно-транспортных документов и актов, которые я
    прикладываю при выполнении операций.

Цели обработки: управление заявками на перевозку, контроль исполнения
маршрута, уведомление о статусе заявки, обеспечение безопасности доступа
к Системе.

Перечень действий: сбор, запись, систематизация, накопление, хранение,
уточнение, извлечение, передача (внутри организации), обезличивание.

Срок действия согласия: до достижения целей обработки либо до отзыва
согласия, но не позднее <срок хранения>.

Отзыв согласия: обращение к администратору Системы. После отзыва доступ
прекращается, данные удаляются или обезличиваются в течение <N> рабочих дней.

Подпись: _________________ / <ФИО> /
```

> Согласие на обработку данных о местоположении (специальная категория,
> ст. 10 152-ФЗ) оформляется **отдельным документом** — с 01.09.2025 это
> требование прямое.
