# Безопасность

Модель угроз, меры защиты и процедуры. Что уже реализовано в коде — в
[`../packages/web/src/api/`](../packages/web/src/api/), что — на уровне
развёртывания, — в [`DEPLOYMENT.md`](./DEPLOYMENT.md).

## Что защищает система

| Механизм | Где | Что даёт |
|---|---|---|
| Сессии со случайным токеном (32 байта, `crypto.getRandomValues`) | `lib/auth.ts` | Токен невозможно подобрать |
| Bearer-токен, сравнение по `timingSafeEqual` в криптооперациях | `lib/auth.ts`, `max/initdata.ts` | Нет атак по времени |
| Проверка подписи initData MAX | `max/initdata.ts` | Мини-приложение — доверенный источник личности |
| Отсечка initData: старше 1 часа — отклоняется | `max/initdata.ts` | Ограничение окна подделки |
| Защита от дублирующихся параметров подписи | `max/initdata.ts` | Нельзя подменить пару параметров |
| Роли admin / dispatcher / driver | `lib/auth.ts` | Разграничение доступа |
| Блокировка входа после 5 ошибок, троттлинг выдачи кода | `lib/access.ts` | Защита от перебора |
| Срок жизни сессий: 12 ч (браузер), 30 дн (Mini App) | `lib/access.ts` | Ограничение окна сессии |
| Авто-приостановка неактивных сотрудников | `lib/access.ts` | Сокращение поверхности доступа |
| Ручной допуск новых сотрудников | `lib/access.ts` | Контроль над тем, кто вошёл |
| Оповещение о входе с нового устройства | `lib/access.ts` | Водитель узнаёт о чужом входе |
| Журнал доступа (`access_events`) | `routes/staff.ts` | След действий по каждому сотруднику |
| Журнал административных действий (`audit_log`) | `lib/audit.ts`, `routes/staff.ts` | Кто, что и когда менял — правку карточек, блокировки, смену настроек, выгрузку и стирание ПДн |
| Журнал доставки событий (`webhook_events`) | `api/index.ts` | Сколько событий MAX пришло, обработано, отброшено как дубль, отклонено по секрету |
| Явное согласие на обработку ПДн | `api/max/webhook.ts` | Отдельный шаг перед активацией; версия согласия хранится в карточке |
| Право на выгрузку и удаление данных | `lib/personal-data.ts` | Ст. 14–17 152-ФЗ: субъект может получить копию и потребовать удаления |
| Политика обработки в открытом доступе | `web/pages/privacy.tsx` | `/privacy` доступна без авторизации |
| Защита от повторной обработки событий MAX | `max/dedupe.ts` | Ретраи MAX не дублируют действия |
| Проверка секрета вебхука (`X-Max-Bot-Api-Secret`) | `api/index.ts` | События принимаются только от MAX |
| Белый список CORS | `core/app.ts` | Чужой сайт не обращается к API |
| Заголовки безопасности + `frame-ancestors` | `core/app.ts`, `Caddyfile` | Защита от кликджекинга и внедрения |
| Корни Минцифры для TLS к MAX | `max/tls.ts` | Проверка сертификата `platform-api2.max.ru` |
| Один пул соединений к БД | `database/client.ts` | Нет исчерпания `max_connections` |

## Модель угроз

### Внешний злоумышленник без учётной записи

| Угроза | Защита |
|---|---|
| Перебор кода входа | Не более 5 попыток → блокировка на 15 минут; троттлинг выдачи кода (1/мин, 5/час) |
| Подделка initData | HMAC-SHA256 + `timingSafeEqual` + проверка возраста |
| Подписка на вебхук чужого адреса | Секрет вебхука; панель показывает список подписок |
| Кража сессии | Токен в `localStorage` (не в cookie), срок жизни ограничен |
| DoS через `/api/cron/tick` | Секрет `CRON_SECRET`; без него — 401 |
| Скан портов и подбор путей | Наружу открыты только 80 и 443; приложение — за Caddy |

### Внутренний пользователь

| Угроза | Защита |
|---|---|
| Водитель видит чужие заявки | Роли: `dispatcherOnly` / `adminOnly` на процедурах; водитель — только свои |
| Водитель видит список сотрудников | `staff.list` — только для админа (история: раньше водитель видел телефоны и действующие инвайты — исправлено) |
| Массовая рассылка уведомлений игнорируется | Персональные фильтры событий, «тихий режим», «только мои заявки» |
| Админ ушёл в отставку, а доступ остался | Авто-приостановка по бездействию + «Доступ до» (окончание договора) |
| Утечка данных через чужую сессию | «Выйти на других устройствах», список сессий в карточке сотрудника |

### Оператор инфраструктуры

| Угроза | Защита |
|---|---|
| Доступ к БД из интернета | Порт БД не публикуется; доступ только из внутренней сети docker |
| Компрометация контейнера | `read_only: true`, `cap_drop: ALL`, `no-new-privileges`, non-root uid 10001 |
| Утечка секретов в образ | `.dockerignore` исключает `.env`; `.env` на хосте — права `600` |
| Доступ к образам и томам | `docker system df`, регулярный `docker builder prune -af` |

## Ротация секретов

Полная процедура — в [`DEPLOYMENT.md`](./DEPLOYMENT.md), раздел «Ротация
секретов». Ключевое:

- `MAX_WEBHOOK_SECRET` менять **только вместе с переподпиской** на вебхук,
  иначе MAX начнёт получать 401.
- Секреты не должны попадать в чат, в коммиты и в файлы репозитория.
- Ключи и пароли, которые пришлось передать в переписке, считаются
  скомпрометированными и меняются.

## Порядок действий при утечке

1. **Определить границы:** что именно утекло, кому, когда.
2. **24 часа** — уведомление в Роскомнадзор (ч. 3.1 ст. 21 152-ФЗ).
3. **Изолировать:** заблокировать скомпрометированные учётные записи, сменить
   секреты, пересоздать контейнеры.
4. **72 часа** — уведомление с результатами внутреннего расследования.
5. **Устранение и выводы:** закрыть причину, обновить модель угроз.

Шаблоны уведомлений — в [`152FZ.md`](./152FZ.md).

## Сторож вебхука

MAX снимает подписку, если endpoint долго недоступен. После этого бот молча
перестаёт получать события — это самая частая «тихая» поломка в проде.

```bash
cat > /etc/cron.d/max-webhook-guard <<'EOF'
*/5 * * * * /opt/dispatch-containers/scripts/max-webhook-guard.sh >> /var/log/max-webhook-guard.log 2>&1
EOF
```

## Проверка перед сдачей

- [ ] `NODE_ENV=production`, `DEV_LOGIN=0`, `MAX_STUB=0`
- [ ] `.env` — права `600`, вне git и вне образа
- [ ] Порт БД не опубликован
- [ ] Контейнер работает от non-root, `read_only: true`
- [ ] CORS не отражает посторонние Origin
- [ ] Заголовки: HSTS, nosniff, `frame-ancestors` с `https://*.max.ru`
- [ ] Ротация `MAX_WEBHOOK_SECRET` → переподписка → события идут
- [ ] Бэкап создан **и восстановлен** в отдельную базу
- [ ] В билде нет внешней аналитики и Google Fonts
- [ ] Сторож вебхука стоит в cron
