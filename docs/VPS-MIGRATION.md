# Перенос на другой сервер

Сценарий: текущий VPS меняется, меняется IP, или домен переезжает на другого
хостинга. Данные и настройки при этом сохраняются.

---

## Порядок действий

### 1. Подготовить новый сервер

См. [`NEW-VPS-FROM-SCRATCH.md`](./NEW-VPS-FROM-SCRATCH.md), шаги 1–2, но **не
запускайте** `bootstrap-fresh.sh` — он создаст новую пустую базу.

Нужно: Docker, код, `.env` (скопированный со старого сервера), домен.

### 2. Скопировать `.env` со старого сервера

```bash
# на старом сервере
scp root@<старый-ip>:/opt/dispatch-containers/.env /tmp/dispatch.env
chmod 600 /tmp/dispatch.env
```

`.env` содержит все секреты: пароль БД, токен бота, секрет вебхука. Передавать
только по защищённому каналу и не класть в репозиторий.

### 3. Скопировать базу

```bash
# на старом сервере
docker compose exec -T db pg_dump -U dispatch -d dispatch --clean --if-exists | gzip -9 > /tmp/dispatch.sql.gz

scp /tmp/dispatch.sql.gz root@<новый-ip>:/tmp/
```

### 4. Поднять новый сервер

На новом сервере:

```bash
git clone --branch main git@github.com:xenus91/DispatchContainers.git /opt/dispatch-containers
cd /opt/dispatch-containers

cp /tmp/dispatch.env .env
chmod 600 .env

# развернуть сервисы БЕЗ перезаписи данных: compose сам применит миграции,
# но база уже создана дампом — сначала поднимаем только db
docker compose up -d db
```

Восстановить дамп:

```bash
gunzip -c /tmp/dispatch.sql.gz | docker compose exec -T db psql -U dispatch -d dispatch -v ON_ERROR_STOP=1
```

Проверить:

```bash
docker compose exec -T db psql -U dispatch -d dispatch -c "SELECT count(*) FROM staff;"
docker compose exec -T db psql -U dispatch -d dispatch -c "SELECT count(*) FROM requests;"
```

Поднять всё остальное:

```bash
docker compose up -d
```

### 5. Переключить DNS

- A-запись домена → новый IP.
- Если IP меняется — дать TTL на распространение (заранее поставить 300 сек).

**Сертификат:** Let's Encrypt выпускается автоматически, когда Caddy видит, что
домен указывает на него. Через несколько минут сертификат перевыпустится.

Если используется сертификат российского УЦ — скопировать `.crt` и `.key` на
новый сервер и смонтировать по инструкции из
[`NEW-VPS-FROM-SCRATCH.md`](./NEW-VPS-FROM-SCRATCH.md), раздел «Сертификат
российского УЦ».

### 6. Проверить вебхук

Подписка MAX привязана к **адресу**, а не к серверу, поэтому при неизменном
домене она остаётся в силе. Но если адрес изменился — переподписаться:

```bash
set -a; . ./.env; set +a
curl -s -H "Authorization: $MAX_BOT_TOKEN" "$MAX_API_BASE_URL/subscriptions"
```

Если нашего URL в списке нет — переподписаться (см. `OPERATIONS.md`).

### 7. Проверить и отключить старый сервер

```bash
curl -s https://<домен>/api/health
docker compose logs --tail=50 app
```

Старый сервер отключать **только после** того, как новый заработал и
вебхук пошёл.

## Если меняется только IP (домен тот же)

Шаги 1–4 и 6–7 те же. DNS: обновить A-запись. Сертификат перевыпустится
автоматически. Вебхук останется подписан на тот же URL — переподписка не
нужна.

---

## Если меняется домен

Дополнительно к шагам выше:

1. В `.env` на новом сервере поменять:
   ```
   DOMAIN=<новый-домен>
   WEBSITE_URL=https://<новый-домен>
   MAX_MINIAPP_URL=https://<новый-домен>
   ```
2. Пересоздать `Caddyfile` под новый домен:
   ```bash
   sed -i "s|старый-домен|новый-домен|g" Caddyfile
   ```
3. Пересоздать приложение:
   ```bash
   docker compose up -d --force-recreate app
   ```
4. **Переподписаться на вебхук** — старый URL больше не работает.
5. В панели MAX обновить адрес мини-приложения на новый домен.
6. Проверить `frame-ancestors` в `Caddyfile` — домен `*.max.ru` в списке должен
   остаться.

---

## Если переносится на другой хостинг с другим часовым поясом

```bash
# в .env
TZ=Europe/Moscow
```

Значение используется и в контейнере приложения, и в контейнере БД. Без него
`Intl` в Alpine считает время неверно.

## Чек-лист переноса

- [ ] `.env` скопирован, права `600`
- [ ] Дамп БД сделан и перенесён
- [ ] На новом сервере база восстановлена, количество строк сходится
- [ ] `docker compose up -d` отработал, `app` — healthy
- [ ] `https://<домен>/api/health` отвечает
- [ ] Мини-приложение MAX открывается (не пустой экран)
- [ ] Подписка на вебхук на месте (`GET /subscriptions`)
- [ ] Бот отвечает в MAX
- [ ] Планировщик живой (индикатор в панели зелёный)
- [ ] Сторож вебхука и бэкап перенесены в cron на новом сервере
- [ ] Старый сервер отключён
